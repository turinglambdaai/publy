# 在任意编辑器写作，通过 Publy 发布

English：[editor-workflows.md](editor-workflows.md) · **简体中文**

**2026-10-30 产品决定：只重点支持 Typora 与 Obsidian，两者共用 Markdown 到公众号草稿流程。** 用户继续在自己喜欢的
编辑器中写作，内容文件留在原位置。Publy 负责公众号排版、预览、发布前检查、
明确投递到**草稿箱**及结果恢复，而不是再造 Markdown 编辑器或搬迁用户的内容库。
本地预览、自托管路径保持免费；未来托管订阅应对可靠交付收费，而不是强迫用户换编辑器。

## 现有开发版的输入方式

| 写作工具 | 接入方式 | 真实能力/边界 |
| --- | --- | --- |
| Typora | 原始 `.md` / `.markdown` 文件路径 | 标准 Markdown 图片相对路径和本地 `typora-root-url`；不用等待 Typora 插件 |
| 其他保存标准 Markdown 的工具 | 仅通用文件读取 | 不开发、不宣传或承诺专用编辑器适配 |
| Obsidian | 现有插件或 CLI 打开 Markdown | 支持 `![[...]]` 等语法；社区三文件安装仍受 #12 阻塞 |
| Notion、飞书、语雀、Word/WPS、Google Docs | **不在范围** | 不计划开发独立集成与连接器 |
| 网页粘贴、手机分享、URL 导入 | **不在范围** | 不列入当前产品开发计划 |

**支持输入文件不等于已经认证某编辑器。** 首先解决常见文件工作流，
再按真实反馈决定哪里值得开发专用集成。

## Typora 最小可用路径

Typora 可以将图片放在原文件附近、相对资源目录中；也支持
`typora-root-url`。Publy 优先从 Markdown 所在目录解析图片的完整相对路径，
不把 `a/logo.png` 和 `b/logo.png` 错配。对于 `/images/xx.png`，
可按 YAML 中的**本地** `typora-root-url` 定位；不会下载远端根目录。
不会修改原始笔记。**隐私提示：**为了离线显示本地图片，预览 HTML 会临时
内嵌图片内容；默认写入系统临时目录，也可以用 `--out` 明确指定保存位置。
预览文件属于私密内容，使用后请删除。远程 HTTP 图片仍保留远程引用，**在浏览器
打开预览时可能联网加载**；`publy check` 本身不联网。

假设目录里有 `article.md` 和 `assets/cover.jpg`：

```md
---
title: 我的第一篇草稿
cover: assets/cover.jpg
---

# 正文

![封面](assets/cover.jpg)
```

当前仅供源码构建后的开发者使用：

```sh
publy check "D:/Notes/article.md" --json   # 离线检查图片和卡片结构
publy preview "D:/Notes/article.md"      # 本地预览内嵌图片，无需服务器
publy preview "D:/Notes/article.md" --no-open --out preview.html  # 不自动打开，便于复核
# 配好有权限的自托管服务，确认目标账号后再执行：
publy publish "D:/Notes/article.md" --account 我的公众号
```

`check` 不登录、不调用远端、不投递草稿；缺图片、封面或卡片结构错误会以
JSON 问题清单呈现，退出码 4；文件输入不合法退出码 2。**当前尚无经过真实
干净电脑验收的普通用户安装包**，详情见 [发行计划](distribution.md)。

**防止误发稿：**开发版 `publy publish` 在发现缺图、封面缺失、公式/SVG
无法正确转换、外链或内嵌 data 图片无法上传时，均在网络请求前以退出码
4 停止。请先用 `check` 检查素材、用 `preview` 查看带醒目提示的
本地预览，再保存草稿。远程图片应先保存到原文章的本地资源目录。
生成的本地 HTML 预览加入严格的浏览器内容安全策略（CSP），阻止
远程图片、脚本和后台请求，内嵌的本地图片仍可显示；用户主动点击链接
仍由浏览器决定是否导航。`check` 本身不联网。

## 商业软件级用户旅程：目标状态，非已交付

1. **打开原文：** 文件选择、拖拽、系统“打开方式”或编辑器快捷入口；
   不要求导入整个库，不在后台复制笔记，不要求用户先配 API/服务器。
2. **检查与预览：** 真实公众号尺寸的预览、主题切换、封面检查；
   本地图片、丢失文件、外链、同名资源必须清楚标注，不能静默漏图或错图。
3. **明确选择动作：** “复制排版内容”与“投递到某公众号的草稿箱”
   是两个不同按钮；投递前显示标题、账号、封面、动作。不得默认群发。
4. **可靠回执：** 区分草稿已确认、重复去重、排程、结果未知和失败；
   超时先按同一个请求身份查询，不盲目重试。
5. **返回写作现场：** 源文件和图片仍在原路径，可继续用 Typora/Obsidian
   编辑；Publy 不管理一份隐形第二数据库或内容副本。

可考虑基于 Rivet 的**轻量发布伴侣应用**，但它绝不承担另一个编辑器的
职责。是否采用 Rivet 取决于三系统安装、无障碍与实际交付验收。

## 优先级与验收

- **P0 内容可信：** 相对路径和同名图片正确、源文件不变、缺失资源阻断
  或显著警告、预览忠实；覆盖中文/空格路径、Windows 盘符、UTF-8、
  相对上级目录、远程图片、危险 HTML、图表/公式与封面。
- **P1 真正零技术安装：** Windows/macOS/Linux 独立发行和更新卸载；
  无需 npm、Node、Racket、CLI、服务器或注册即可完成第一次本地预览；
  键盘/读屏操作、深浅色、错误解释与界面美观都要验收。
- **P2 值得付费的交付服务：** 引导绑定公众号、固定出口 IP、权限与安全检查、
  账户权益、配额、可靠任务、失败恢复、退款取消、可追踪记录和支持服务。
  Commerce/Permit 是商业状态权威，未获真实商户准入前不开放收款。
- **P3 更多来源：** 文件导入与保真测试优先；再按用户实际需求扩展专用
  编辑器集成，不以支持多少品牌为 KPI。

每条工作流必须记录：干净安装、样例文件及资源清单、预览比对、
复制/草稿投递结果、离线和异常处理、升级与卸载、是否保留原文件。
**编译通过不等于商业产品验收。**
