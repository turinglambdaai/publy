# Publy 的发布平台取舍（2026-10-30）

[English](platform-strategy.md) · **简体中文**

**状态：现行产品范围决定，不代表功能实现或平台获批。**

## 只解决一个付费用户问题

Publy 服务的是“在自己喜欢的编辑器写文章，准确预览、检查素材，明确保存到
选定微信公众号的草稿箱，并能确认或恢复结果”的创作者。不做第二个
Markdown 编辑器，不搬运和复制用户的内容库，不自动群发。

**输入可以兼容更多编辑器，输出暂时只做好一个平台。**
Typora、Obsidian、VS Code、MarkText 等共用 Markdown 输入与素材处理管线，
不能把它理解成同时要维护十几个发布平台。每多一个目的地，意味着新的
身份授权、API 政策、内容转换、状态恢复、客服与长期维护负担。

## 接入决策

| 目的地 | 优先级 | 边界 |
| --- | --- | --- |
| 微信公众号 | **P0：唯一现阶段正式发布目标** | 官方草稿 API；优先完善安装、图片、预览、投递确认、结果未知恢复和托管运营 |
| 知乎 | **候选/调研队列，不承诺开发时间** | 技术长文契合，但需验证正常用户可合法申请的官方授权、发布接口及持续维护条件；不使用 Cookie、模拟登录或内部接口绕过准入 |
| WordPress、Ghost、DEV/Forem | **暂缓** | 有相对明确的文章发布技术条件，并不等于现在值得投入 |
| 小红书、抖音、微博、头条、Medium 等 | **不在当前开发路线图** | 内容形态、平台政策和权限差异大；研究资料不是支持承诺 |
| 本地格式输出 | **有限保留** | HTML、图片卡片和预览可以继续使用，但不宣称已经适配任何平台的粘贴兼容性 |

## 什么时候重新考虑知乎？

优先完成：

1. **公众号 P0 体验**：原 Markdown 及图片正确、预检查、预览与复制、
   草稿投递明确、重复与超时恢复可靠；Windows/macOS/Linux 干净安装
   和实际编辑器验收通过（#7、#8、#12、#14、#15、#25、#26）。
2. **真正可付费的服务**：稳定出口 IP、公众号绑定、凭据安全、
   Commerce/Permit 实时权益与配额、退款取消、恢复和客服可交付
   （#17）。当前禁止假设公开托管已可出售。
3. **唯一候选知乎的准入复评**：确认合法持续的官方授权和普通用户接入；
   至少有 5 位不同的潜在用户表达可复现的持续发布需求；内容格式
   保真、开发及长期维护成本可控；有助于付费转化或留存。
   条件不满足，就只保留本地导出功能，不做官方发布适配器。

**不做**全平台一键群发、通用 CMS、跨平台统一排程大工程、
另一个全文编辑器、主题交易市场或以平台数量作为产品 KPI。

## 工程要求

核心渲染与预检保持编辑器中立；现阶段只有微信公众号官方
草稿投递属于生产目标。不为假想平台提前构造庞大 Provider 框架，
不在客户端堆积各平台授权信息。后续每个目标必须单独提供真实
用户、官方权限、隐私、发布回执、故障恢复和维护成本证据后才能进入开发。

该决定不修改现有许可证、收费门禁、实际 API 授权或发行状态。
